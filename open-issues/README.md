# Open Issues on This Branch

What is currently broken on our EDG contracts branch -- whatever its origin.
If you hit something while using this front end, look here first: a row
means we already know, and tells you whether there is a way around it.

A row is removed, and any file it points to in this directory deleted, as soon
as the issue is **fixed on this branch**.  Git history is the record; nothing
is archived in place.

**This file is the only ledger of owed work on this branch.**  Every known
defect and deferral is a row in the first table, and every owed
task (a missing test, an owed run, unimplemented scope) is a row in the
task table; cleanups (style, comments, dead code, duplication) are rows in
[`CLEANUP.md`](CLEANUP.md).  Review notes, plans and milestone notes written
elsewhere are records of reasoning, not lists of work: an item found there
that is not a row here has been lost.  Record it here first, then write
anywhere else.  Divergences are recorded in their own table,
[Divergences](#divergences), and are not owed work.  Source, tests and this
directory never record work owed to another compiler; such work is a row in
that compiler's own ledger.

This is a different question from the one
[`../bug-reports/`](../bug-reports/README.md) answers.  That directory tracks
bugs that reproduce on **stock upstream** EDG, including ones we have already
fixed here, and a row there survives until *upstream* fixes it.  An upstream
bug we have not yet fixed appears in both; its single writeup lives in
`bug-reports/` and the row below links to it.

Contracts are not in upstream EDG, so a contracts-dependent bug has nothing
upstream to reproduce against and is not tracked in `bug-reports/`.  Such
issues are branch-only by definition and their writeups live here.

## Layout

One directory per issue, `edg-N/`, the same shape as
[`../bug-reports/`](../bug-reports/README.md) and as the GCC and Clang forks'
trackers, so an issue that turns out to reproduce on stock can move across
without being reshaped.

IDs come from one sequence, shared with `bug-reports/` and with the task and
cleanup tables, and are never reused.  Allocate from the line above and
increment it.  Rows are deleted, so the highest ID visible is not a reliable
counter.

`--` in the Upstream column means the issue is ours alone with nothing
upstream to link -- for a contracts-dependent issue that is always the case.
`None found (searched <date>)` means upstream's tracker was searched and
nothing matched; `UNKNOWN` means nobody has looked.

**Kind** is one of `defect` (wrong, and we intend to fix it) or `deferred`
(known, currently out of scope) in the first table, `divergence` (our
compilers disagree and the standard does not clearly settle which is right)
in the [Divergences](#divergences) table, and
`task` in the task table.  A defect row always has a writeup and a watch test in
`tests/tests/contracts/openbugs/`.  edgy has no XFAIL: the watch test's
recording IS the current wrong behavior, so a fix shows up as a deviation in
the contracts suite -- that is the signal to delete the row (and, if the
same bug is open in GCC or Clang, to check their mirrors).

**A new issue is always recorded as `defect` when it is discovered.**  It
becomes `deferred` only when the user has explicitly said they do not want
to expand scope far enough to fix it -- never by an agent's own judgement
that a fix looks hard or invasive.
