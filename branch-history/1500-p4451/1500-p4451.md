## Rationale

P4451 (P4451R2, "Early Adoption of an Always-Enforced Label"), as our GCC's
`-fcontracts-p4451` (notadragon_wg21 DECISIONS.md E173, E174, E216, E218):
with `--[no_]contracts_p4451` (enabling contracts; an error in C; passed to
g++ by the drivers as `-f[no-]contracts-p4451`), an assertion-control
specifier `< id-expression >` after `pre`, `post` or `contract_assert`,
naming `std::contracts::controls::enforced`, makes the contract assertion a
terminating one, every evaluation of which uses a terminating semantic.  It
stands on the C++26 facility alone, and comes directly after it, before
every other paper.

P4451 is part of C++26, so the C++26 language mode (and every later one)
enables `--contracts_p4451` while contracts are on, unless
`--[no_]contracts_p4451` is given (DECISIONS.md E220); before C++26 nothing
but the option itself does, and with `--no_contracts` it stays off without
an error.  edg-gxx gives `-std=` and `-f[no-]contracts-p4451` to both the
front end and g++, which enables it in C++26 the same way.

`scan_assertion_control_specifier` takes the specifier at its `<` (and
`curr_token_starts_labeled_contract_specifier` lets `pre<` end a trailing
return type): under the option it marks the assertion (`is_terminating`;
`mark_contract_terminating`) and caches the tokens between the angle
brackets in `label_token_cache`; without it the specifier is pointed at
`--contracts_p4451` and skipped.  A terminating assertion has no label, and
nothing in the ABI changes.  `terminating_contract_semantic` gives it a
terminating semantic: enforce for a configured ignore or observe, and
quick_enforce for the checks the front end makes for the C-generating back
end, the only terminating semantic there.  The function's declarations must
agree on the specifier (both have it or neither does, however spelled).

[basic.contract.control] is checked where the predicate is scanned (a
member function's specifier when its class is complete, with the parameters
in scope; a real instantiation is not checked again): the cached tokens must
be an id-expression that is not dependent, and ordinary name lookup for it
must find the variable that qualified lookup of
`std::contracts::controls::enforced` finds, declared before that point
(libstdc++ declares it in `controls::inline __p4451`).  So a qualified name,
a namespace alias, and an unqualified name found through a using-directive
or using-declaration all name it; an unqualified name that finds nothing is
an error.  The lookups' own diagnostics are suppressed, and each ill-formed
specifier gets one error saying why ("assertion-control-specifier must name
std::contracts::controls::enforced; ...").

The C++-generating back end puts the specifier out as
`<::std::contracts::controls::enforced>` (`gen_contract_label`), for g++,
which chooses the semantic and makes every run-time check.
`__cpp_contracts` is P4451R2's 202611L, and in GNU and Clang modes
`__gcc_contracts_p4451` (`__clang_contracts_p4451`) 202611L is predefined,
by which libstdc++ declares the label and raises `__cpp_lib_contracts`.

The tests are those of `tests/tests/contracts/p4451/` and of the imports of
the gnu_gcc fork's P4451 tests in `tests/tests/contracts/imported_p4451/`
that need only `--contracts_p4451`; the rest go with the last paper they
need (2400-p3595, 2900-umbrella-option, 3000-p3097, 4210-p3400-facets,
4285-p4451-under-p3400, 4660-p4451-run, 4900-p4405,
6910-p4451-callerside-later, 6995-contracts-option-rule).

## Compile gap

None of its own: what P4451's lines use is upstream's or the base
facility's.  The base facility itself does not build at this point
(EDG-189).  Later papers add to it rather than replace it: `2400-p3595`
gives contract_semantic_for, through which `terminating_contract_semantic`
is applied; `4200-p3400-core` makes the specifier a label under
`--contracts_p3400` (and, with neither option, one not naming `enforced`),
has `pre<` end a trailing return type for a label too, and has
`--contracts_p3400` imply `--contracts_p4451`, as `2900-umbrella-option`
has `--contracts_p3850`; `4210-p3400-facets` gives a terminating assertion
the allowed set of P3400's `controls::enforced` and chooses its semantic
as for that label (after which `terminating_contract_semantic` changes
nothing), and `4900-p4405` adds prove to the set and lets P4405's analysis
split apply to it; `3000-p3097` raises `__cpp_contracts` further;
`6995-contracts-option-rule` adds the rest of the option rule.
