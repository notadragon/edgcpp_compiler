## Rationale

Implement P3290, "Integrating Existing Assertions", the front end's part of
which is only a predefined macro: `--[no_]contracts_p3290` (implied by
`--contracts_p3850` unless given, and itself enabling contracts unless
`--[no_]contracts` is given; an error in C mode) predefines, with contracts
enabled, the vendor macro of the emulated compiler -- `__gcc_contracts_p3290`
in GNU mode, `__clang_contracts_p3290` in Clang mode, both `202609L`, as the
GCC and Clang contracts implementations do (DECISIONS.md E19).  Their
standard libraries key everything else on it: libstdc++'s
`bits/assert_contract.h` redefines `assert` to call
`__cxa_handle_cassert_violation` (when `__STDC_WANT_ASSERT_USES_CONTRACTS__`
is defined), `<version>` defines `__cpp_lib_contracts_api` and
`__cpp_lib_assert_can_use_contracts`, and `<contracts>` declares the
`handle_*_contract_violation` functions.  Through edg_gxx.sh the front end
expands those headers and g++ links `libstdc++exp`, so nothing else is
needed; edg_gxx.sh passes `-f[no-]contracts-p3290` to both, and edgy's
`eccp-gxx` and `eccp.sh` pass the option on.

Tests: `contracts/p3290/` (the macro, and `assert` reaching the violation
handler) and 39 GCC and Clang imports in `contracts/imported_p3290/`.
