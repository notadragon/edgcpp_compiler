## Rationale

Implement P3097, "Contracts for C++: Support for Virtual Functions"
(adopted into the working draft; no feature-test macro of its own: GCC
raises `__cpp_contracts` to `202609L`, and so does this).
`--[no_]contracts_p3097` -- implied by `--contracts_p3850` unless given,
enabling contracts unless `--[no_]contracts` is given, an error in C mode
-- lets a virtual function have function contract specifiers (the P2900
restriction applies only without it).  There is no contract inheritance:
an overrider's assertions are its own.

In a virtual call the statically chosen function's assertions (the
interface) are checked around the final overrider's (the implementation):
interface preconditions, implementation preconditions, the body,
implementation postconditions, interface postconditions.  A qualified call
and a call through a pointer to member check only the function called.  The
front end does this in constant evaluation: `process_call_work` keeps the
statically chosen function and the unadjusted `this` across the virtual
dispatch, and `evaluate_function_contracts` evaluates the interface's
assertions with `this` mapped to that subobject (the parameters are the
overrider's, by position).  Each postcondition sees its own covariant
result: the overrider's before the adjustment to the static type, the
interface's after.

Through edg_gxx.sh (which passes `-f[no-]contracts-p3097` to both the front
end and g++; edgy's `eccp-gxx` and `eccp.sh` pass it on) g++ builds the
interface wrappers and checks both at run time.

In the checks the front end generates for the C-generating back end, a
virtual call of a function with contract assertions calls instead (IL
lowering redirects it) its interface wrapper, a compiler-generated,
non-virtual inline member function made on the first virtual call
(`make_contract_interface_wrapper`, recorded in
`a_routine::contract_interface_wrapper` and `contract_interface_target`),
whose definition checks the function's preconditions and postconditions as
any definition does (1100-p2900-base-lowering's prologue, captures and
epilogue) around a virtual call of it (`add_contract_interface_call`).  That
call passes the wrapper's arguments on as they are: an argument passed by
copy constructor is passed on as an lvalue, whose address IL lowering
passes, which is the caller's copy's; a class result initializes the
wrapper's result directly, so IL lowering returns it to the caller's object.
A violation reports the virtual function's name.  A C-variadic function gets
no wrapper, its ellipsis arguments not being passable (EDG-88).

Tests: `contracts/p3097/` (the order of checks in constant evaluation,
`this` and covariant results under multiple inheritance, qualified and
pointer-to-member calls, the macro, the restriction without the option) and
67 GCC and Clang imports in `contracts/imported_p3097/`.

## Compile gap

The restriction in 1060-p2900-base-sema-core (`class_decl.c`) tests
`contracts_p3097_enabled`, which this commit adds, and
1090-p2900-base-sema-constexpr's `evaluate_function_contracts` already has
the `this_address` parameter and its callers pass NULL for it.
1100-p2900-base-lowering's `prepare_contract_checks_for_lowering` takes an
interface wrapper's specifiers from its virtual function, and its
`prepare_contract_interface_checks` serves the wrapper defined here.
