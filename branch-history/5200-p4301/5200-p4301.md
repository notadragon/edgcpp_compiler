## Rationale

P4301, "Context reports for the contract-violation handler" (M14b): with
`--[no_]contracts_p4301` (implied by `--contracts_p3850` unless given, and
enabling contracts; an error in C; passed to the front end and g++ by the
drivers as `-f[no-]contracts-p4301`), `__cpp_contracts_report` is predefined
as 202609L, as our GCC does.  The feature is the library's: libstdc++
declares `contract_violation::report()` when the macro is defined
(`__cpp_lib_contracts_report`), and libstdc++exp defines it.

The front end routes no sanitizer, so nothing it builds carries a report:
with the C-generating back end every violation (through libcontracts'
`__c_contract_check_noexcept`) has a null `report()`.  Through edg_gxx.sh g++
gets the option, so a `-std=c++23 -fcontracts-p4301` program links the
contracts runtime.

The tests are `tests/tests/contracts/p4301/` and the imports in
`tests/tests/contracts/imported_p4301/` (GCC's and Clang's
`p4301-report-ftm-undefined` and `p4301-report-no-flag` were imported with
the base facility).
