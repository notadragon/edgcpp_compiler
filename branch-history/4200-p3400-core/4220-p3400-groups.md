## Rationale

The group names of a P3400 label, matched by configuration entries where
the front end chooses a semantic: in constant evaluation and in the checks
it generates for the C-generating back end (M11c).  g++ applies them at run
time from the labels put out as written (4200-p3400-core) and the group
options edg_gxx.sh passes it (2400-p3595).

When the label's facets are resolved (4210-p3400-facets), its group_names
member is read through <contracts>' combined label, so as the library's
identification_label concept finds it, a combined label's being the sorted
union of its parts' (`resolve_contract_label_groups`, in expr.c): the number
of names from its size, and each name character by character, as integer
constants, whether an array of characters or of pointers to them.  Empty
names are skipped, as in GCC.  They are recorded as
`a_contract_specifier::label_groups`, newline-separated (walked, copied to
file scope with the predicate).

`config_entry_matches` (contract_config.c) matches an entry's group with a
label group that is the same or of which it is a prefix ending before a
".", GCC's rule; an entry with a group no longer matches nothing.

The test is `tests/tests/contracts/p3400groups/`.
