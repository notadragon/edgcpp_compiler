## Rationale

The group names of a P3400 label, matched by configuration entries where
the front end chooses a semantic: in constant evaluation and in the checks
it generates for the C-generating back end (M11c).  g++ applies them at run
time from the labels put out as written (4200-p3400-core) and the group
options edg_gxx.sh passes it (2400-p3595).

When the label's facets are resolved (4210-p3400-facets), and also without
<contracts>, its group_names member is read as GCC reads it
(`resolve_contract_label_groups`, in expr.c): a const member that is a range
whose elements convert to std::string_view (or, without <string_view>, to
const char *), walked as a range-based for walks it -- an array, begin and
end as members or found by argument-dependent lookup -- so a span, an
initializer_list or a combined label's union of its parts' names is read in
full.  The front end defines, at the start of the translation unit, a
function template that walks the range once and yields the number of names,
an array of their lengths, or an array of all their characters
(`enter_contract_label_group_reader`, in symbol_tbl.c), testing each
requirement with if constexpr so that no label makes an instance
ill-formed, and constant-evaluates three calls of it, so the reading costs
time linear in the size of the names.  Each name is read within the
full-expression that dereferences the iterator, so an iterator may return
its names by value.  Empty names are skipped, as in GCC.  They are recorded
as `a_contract_specifier::label_groups`, newline-separated (walked, copied
to file scope with the predicate); a byte 0, newline or 1 inside a name is
stored as the byte 1 followed by '0', 'n' or '1', so every name is kept
whole.  A name is the whole view, NUL bytes included (notadragon_wg21
DECISIONS.md E191 (a)), and is matched on all of its bytes (E192 (2)):
"safety\0x" is not in safety, "safety.x\0y" is.  A const char * name ends
at its NUL.

A group_names that is such a range but cannot be read is an error, as in
GCC, never a label silently in no group (which would configure its
assertions as unlabelled): "the group_names facet of assertion-control
object T must be usable in a constant expression" when a reading is not a
constant expression (undefined behavior in a begin, a name that is not a
constant, the --max_cost_constexpr_call limit), and "... holds more than
4096 names" for a range or array of more names (notadragon_wg21
DECISIONS.md E187, E190), counted before any name is read.  An absent
or wrongly shaped group_names yields 0 from the reader and stays
undiagnosed.  Names are read in full, whatever their length.

`config_entry_matches` (contract_config.c) matches an entry's group with a
label group that is the same or of which it is a prefix ending before a
".", GCC's and Clang's rule, comparing every byte of the label's name; an
entry with a group no longer matches nothing.  As in GCC and Clang, the
P3100 group ub:conv.lval.valid.representation.bool.enum, named as one but
whose leaves .bool and .enum are not within its name, also selects the
groups within each leaf (DECISIONS.md E125 (a)).

The tests are `tests/tests/contracts/p3400groups/` (`ranges` reads the
range forms without <contracts>, for the semantic of a run-time check;
`read_errors` the errors and the limits, `reported_once` that each is
reported once, `read_string_view` names with NUL bytes in constant
evaluation, and `run_string_view{,_cgen}` at run time under each back
end, both with configured groups that are prefixes of such names and the
combined group's leaves; `combined_leaf` the combined group and
`name_bytes` names holding a newline, the byte 1 or a NUL) and GCC's `p3400-identification-label-range`,
`p3400-combined-label-nesting`, `p3400-group-names-{not-constant,ops-limit}`
and `p3400-group-names-too-many{,-string-view}` imports in
`imported_p3400/gcc/`.
