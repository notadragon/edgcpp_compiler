## Rationale

The facets of a P3400 label that bear on the evaluation semantic, applied
where the front end chooses one: in constant evaluation, and in the checks
it generates for the C-generating back end (M11b).  The run-time facets of
the generated C++ are g++'s, which gets the labels as written
(4200-p3400-core).

When a label is scanned and is not dependent
(`resolve_contract_label_facets`, in expr.c), its allowed_semantics and
compute_semantic facets are probed through <contracts>' own combined label,
`empty_label | label` (`probe_contract_label_facet`, an expression scanned
from cached tokens with diagnostics suppressed): its members exist exactly
when the library's concepts find the label's facet (a public member called
on a const object), and its compute_semantic passes the label's a non-const
lvalue, as GCC's probing does.  An absent facet is no error; one that is not
a constant expression is, with GCC's text, as is an empty allowed set.  The
results are recorded on the contract specifier
(`label_allowed_semantics`, `label_computed_semantics`).  Without
<contracts> a label has no facets.

`contract_semantic_for` adjusts the configured semantic with
`apply_contract_label_facets`: the best fit in the allowed set (GCC's
`contract_semantic_best_fit`: itself, else the nearest that checks more,
else the nearest that checks less; none: observe in constant evaluation,
enforce otherwise), then compute_semantic's result, which must be allowed
too.  An error is diagnosed once for each assertion, with the function
definition or the contract_assert statement (`resolve_contract_semantics`),
where GCC resolves the semantics.  For the C-generating back end only ignore
and quick_enforce are allowed outside constant evaluation (E2); a label that
computes another is an error naming that restriction.

`compute_message` gives the message of constant-evaluation diagnostics
(`label_message`, walked, copied to file scope with the predicate), kept
apart from the message put out for g++, which applies the facet itself; a
compute_comment facet must be a constant expression.

A facet error of a non-dependent label in a template that is never
instantiated is not diagnosed (GCC diagnoses it): the facets are resolved for
the instances.

The tests are `tests/tests/contracts/p3400facets/`; the P3400 imports that
need the facets are among `imported_p3400/` (4200-p3400-core).
