## Rationale

Implement P3099, "User-defined diagnostic messages for contract
assertions": with `--[no_]contracts_p3099` (implied by `--contracts_p3850`
unless given, enabling contracts unless `--[no_]contracts` is given, an
error in C mode), `pre`, `post` and `contract_assert` take a
diagnostic-message after the predicate, `pre(x > 0, "x must be positive")`,
and `__cpp_contracts_message` is predefined as `202609L` (GCC's value).

`scan_contract_diagnostic_message` scans it after the predicate and keeps
its text in the contract specifier (`a_contract_specifier::message`, a
string beside the comment, copied to file scope and walked with it).  Only
a string literal is supported: an unevaluated string, so an encoding prefix
is an error; the C++26 form that is a constant expression providing
`size()` and `data()`, for which the front end has no machinery even in
`static_assert`, is diagnosed as not yet supported (EDG-72).  A violation
in constant evaluation is reported as "contract predicate is false in
constant expression (MESSAGE)", as GCC does; two declarations of a function
give the same message, as text, or none ("mismatched contract diagnostic
message in declaration").  The C++-generating back end prints the message,
re-escaped, after the predicate, and g++ (given `-fcontracts-p3099` by
edg_gxx.sh) passes it to the violation handler as
`contract_violation::message()`.  The C-generating back end checks only
quick_enforce, which calls no handler.

Tests: `contracts/p3099/` (constant evaluation, redeclarations, the
unsupported forms, the macro, the syntax without the option, and the
handler's view of escaped messages through edg-gxx) and 23 GCC and Clang
imports in `contracts/imported_p3099/`.

## Compile gap

1040-p2900-base-parse's `scan_contract_predicate` already returns the
message (its callers pass `&csp->message`) and calls
`scan_contract_diagnostic_message`; 1090-p2900-base-sema-constexpr's
`finish_contract_evaluation` already reports it; and the C++-generating back
end's printing of contract assertions (1020-p2900-base-il) already calls
`gen_contract_message`.  All of these are defined here.
