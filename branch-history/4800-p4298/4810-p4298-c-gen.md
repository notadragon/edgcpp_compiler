## Rationale

The noexcept semantics of P4298 in the checks the front end generates for
the C-generating back end (M13b): with that back end E2 now admits
noexcept_observe and noexcept_enforce besides ignore and quick_enforce, since
they let no exception escape a check either -- on the command line (a
noexcept semantic that falls back to observe or enforce without
`--contracts_p4298` is rejected then), from a configuration entry
(`check_entry_semantic`), and from a label's facets.

A violation calls libcontracts' `__c_contract_check_noexcept` with the
predicate's text, the file, function and line, the assertion kind and the
semantic (`contract_noexcept_violation_call`, from `contract_violation_call`),
through a static inline noexcept function that the front end defines from
source text in every translation unit with P4298
(`enter_contract_noexcept_check_routine`, with the libcontracts entry
predeclared extern "C").  libcontracts terminates on a C++ exception of its
own runtime; a violation handler the front end compiled throws with the
front end's runtime, which the noexcept function's terminating frame (or
its inlined copy's) catches.  After a handler returns, noexcept_observe
continues and noexcept_enforce aborts (libcontracts').  A violation by an
exception from the evaluation of the predicate (the check's handler, see
1100-p2900-base-lowering) calls a second such function,
`__edg_contract_check_noexcept_exception`, which builds a data block of the
contracts ABI with the location and the comment (vendor generic) and reports
it with the kind, the semantic and the evaluation_exception detection mode
through libcontracts' `__dispatch_with_override_core` (predeclared extern
"C" likewise).

A replacement `::handle_contract_violation` is marked in the IL
(`a_routine::is_contract_violation_handler`) and put out with the C-linkage
alias `__handle_contract_violation` (`dump_contract_violation_handler_alias`,
as the `__tls_init` alias is), the name by which libcontracts calls it, as
GCC emits it.  eccp.sh links libstdc++exp (its default handler and
terminate-on-throw barrier forced in by `-u`), libcontracts and then
libstdc++, which libstdc++exp needs (a static `-lstdc++` earlier on the line
would not do), when the objects call `__c_contract_check_noexcept` or
`__dispatch_with_override_core`.

A record with more than those -- a P3099 message, or a P3400 label's computed
comment and message, local violation handler and query function -- goes
through a third function, `__edg_contract_check_noexcept_block`, which builds
a data block with the location, comment and message and, when not null, the
local handler, the query function and the label's address (the ABI's fields
0x01 to 0x06), and dispatches it with either detection mode
(`contract_record_violation_call`).  For an assertion with a label the check
calls a function template the front end defines likewise,
`__edg_contract_check_noexcept_label<contract_violation>`, with the label
combined with `<contracts>`' empty_label, whose members exist exactly when
the label's facets satisfy the library's concepts
(`contract_label_violation_call`, expr.c): it applies compute_comment and
compute_message and passes handle_contract_violation (whose result, if not
void, tells whether the violation is handled, so that the global handler is
not called) and query through function pointers, as GCC passes them.  Under
`--contract_violation_information=none` no message is passed and no comment
or message is computed (6990-contract-violation-information).

The tests are `tests/tests/contracts/p4298cgen/` and the updated
`p4298/nonthrowing_cgen.sft.cpp` (4800-p4298's).
